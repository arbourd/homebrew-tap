# homebrew-tap

Personal Homebrew tap: formulae in `Formula/`, casks in `Casks/`.

## Gotchas

- `Formula/go.rb` is generated by `tools/go` (`go run ./tools/go > Formula/go.rb`), run daily by
  `.github/workflows/go-update.yml`, which opens a "Go vX.Y.Z" PR. Change the template in
  `tools/go/main.go`, not the formula. The workflow skips PR creation on `pull_request` events, so
  editing it only dry-runs the generator.
- The other formulae are generated by `tools/formulae` (`go run ./tools/formulae <name>`), run daily by
  `.github/workflows/formulae-update.yml`, which opens a "<name> X.Y.Z" PR per formula. It reads
  version and sha256 from the latest GitHub release (asset `digest`). Change the registry (`tools/formulae/formulae.yaml`, including each `repo`) or the template
  in `tools/formulae/main.go`, not the formulae. The workflow matrix comes from `go run ./tools/formulae --list`.
  To add a project: add a `formulae.yaml` entry. Releases must be GoReleaser-style
  `<name>-v<ver>-<os>-<arch>.tar.gz` assets with a GitHub `digest`, unless the entry has a `urls` map
  (platform suffix like `darwin-arm64` -> full URL with `#{version}`, every non-skipped platform required).
  Assets still need a GitHub `digest`.
  Until each project's GoReleaser `brews:` block is removed, its releases still push these files.
- `formula.yml` skips Linux for a formula only if it has a bare `depends_on :macos` line.
  A versioned form (`macos: :ventura`) is still tested on Linux.
- Pin third-party actions to release tags, not SHAs. Dependabot bumps them.
- `Casks/orca.rb` is bumped daily by `cask-bump.yml`, which opens PRs with `GITHUB_TOKEN`, so
  `cask.yml` runs on them in an approval-required state (`action_required`). The workflow's last
  step polls for those runs and approves them. Keep `--full-name` on `brew bump --cask`: homebrew/cask has an
  unrelated `orca`, and a bare name makes `bump-cask-pr` target that one.
- `cask.yml` needs at least one cask in `Casks/` (an empty matrix errors). If the last cask is
  removed, disable both jobs with `if: false`.

## Checks

- Generator: `go vet ./... && go test ./... -race && go run ./tools/go` (`go run ./tools/go` hits go.dev).
  `go run ./tools/formulae <name>` hits the GitHub API; set `GITHUB_TOKEN` to avoid rate limits.
- After changing a template, run `go test ./tools/go ./tools/formulae -update` to regenerate the golden files, then review the diff.
- Brew tests run with `XDG_CONFIG_HOME` set to a nonexistent `testpath/.config`; tools that need it must `mkpath` it in the formula `test`.
- Brew tests are sandboxed to `testpath`: writes elsewhere (e.g. the real Trash) fail with a permission error. Prefer offline tests (local git repos over cloning from GitHub).
- To run one formula's test: `go run ./tools/formulae <name> > "$(brew --repository)/Library/Taps/arbourd/homebrew-tap/Formula/<name>.rb"`, then `brew test arbourd/tap/<name>` (it must be installed), then `git checkout` the file in the clone.
- Brew: mirror the steps in `formula.yml` / `cask.yml`. Symlink the checkout first
  (`ln -s "$PWD" "$(brew --repository)/Library/Taps/arbourd/homebrew-tap"`) and set
  `HOMEBREW_GITHUB_API_TOKEN` for `--online` audits. If the tap is already installed as a real
  clone, brew edits that clone, not the checkout, so `git checkout` it after write-only tests.
