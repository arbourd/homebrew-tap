# homebrew-tap

Personal Homebrew tap: formulae in `Formula/`, casks in `Casks/`.

## Gotchas

- All formulae are generated by `tools/formulae` (`go run ./tools/formulae <name>`). Change the
  registry (`tools/formulae/formulae.yaml`, including each `repo`) or the template in
  `tools/formulae/main.go`, not the formulae. Update `formulae.schema.json` with any `Spec` field change.
  `go` uses `source: go` (reads go.dev, no `repo`, so it sets `homepage` and `release_notes`); every
  other entry reads GitHub releases. `release_notes` is the PR body link and must contain `#{version}`;
  `homepage` and `release_notes` default to the GitHub repo and its release.
- To add a GitHub project: add a `formulae.yaml` entry. Every asset needs a GitHub `digest`. Assets
  default to GoReleaser-style `<name>-v<ver>-<os>-<arch>.tar.gz` names; a `urls` map (platform suffix
  like `darwin-arm64` -> full URL with `#{version}`, every non-skipped platform required) overrides
  that naming. Until the project's GoReleaser `brews:` block is removed, its releases still push
  these files.
- The update workflows skip PR creation on `pull_request` events, so editing one only dry-runs it.
- Bot PRs are opened with `GITHUB_TOKEN`, so `formula.yml` / `cask.yml` runs on them sit in
  `action_required`. Each bump workflow's last step approves them by matching the PR branch name
  (`<name>-<digit>`, `bump-`); keep that in sync with each `branch:` in the workflows.
- `formula.yml` skips Linux for a formula only if it has a bare `depends_on :macos` line.
  A versioned form (`macos: :ventura`) is still tested on Linux.
- Pin third-party actions to release tags, not SHAs. Renovate bumps them (`.github/renovate.json`).
- `cask-bump.yml` bumps `Casks/orca.rb`. Keep `--full-name` on `brew bump --cask`:
  homebrew/cask has an unrelated `orca`, and a bare name makes `bump-cask-pr` target that one.
- `cask.yml` needs at least one cask in `Casks/` (an empty matrix errors). If the last cask is
  removed, disable both jobs with `if: false`.

## Checks

- Generator: `go vet ./... && go test ./... -race && go run ./tools/formulae go` (hits go.dev).
  `go run ./tools/formulae <name>` hits the GitHub API; set `GITHUB_TOKEN` to avoid rate limits.
- After changing a template, run `go test ./tools/formulae -update` to regenerate the golden files, then review the diff.
- Brew tests run with `XDG_CONFIG_HOME` set to a nonexistent `testpath/.config`; tools that need it must `mkpath` it in the formula `test`.
- Brew tests are sandboxed to `testpath`: writes elsewhere (e.g. the real Trash) fail with a permission error. Prefer offline tests (local git repos over cloning from GitHub).
- Brew: mirror the steps in `formula.yml` / `cask.yml`. Symlink the checkout first
  (`ln -s "$PWD" "$(brew --repository)/Library/Taps/arbourd/homebrew-tap"`) and set
  `HOMEBREW_GITHUB_API_TOKEN` for `--online` audits. If the tap is already a real clone, brew edits
  that clone, not the checkout, so `git checkout` it after write-only tests.
- To test one formula: `go run ./tools/formulae <name> > "$(brew --repository)/Library/Taps/arbourd/homebrew-tap/Formula/<name>.rb"`,
  then `brew test arbourd/tap/<name>` (it must be installed), then `git checkout` the file in the clone.
